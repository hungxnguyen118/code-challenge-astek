# OWASP Top 10 security acceptance matrix

Baseline: **OWASP Top 10:2025**, checked 2026-11-12 against the [official release](https://top10.owasp.org/2025/) and [introduction](https://top10.owasp.org/2025/0x00_2025-Introduction/). OWASP describes this as an awareness document about major web-application risks. The controls, tests and numeric targets below are this project's acceptance criteria, not OWASP certification requirements.

## Scope and status

Current architecture: browser-local file ingestion/analysis/export, a Next.js application, bundled public samples, no application authentication, inventory database or upload API. Hosting, dependency installation and build/distribution remain security boundaries even though inventories are parsed locally.

Statuses: **PARTIAL** = some implementation/test evidence exists but acceptance is incomplete; **NOT VERIFIED** = evidence not collected; **N/A (conditional)** = no corresponding application feature, with the reason and reactivation trigger recorded. N/A is never counted as PASS. There is no overall OWASP PASS at this baseline.

These are project-specific mappings; one control can mitigate several categories. An ordinary extraction bug is not automatically an exploitable vulnerability. Record security impact and functional impact separately.

## Measurable gates

| Gate | Definition and target | Current measurement |
|---|---|---|
| Scope coverage | All 10 categories have applicability, rationale, control/evidence requirement and status: 10/10. | 10/10 documented; this is documentation coverage only. |
| Control verification | PASS controls / applicable controls, with the control list frozen for the reviewed release. Target 100%; PARTIAL and NOT VERIFIED remain in denominator; justified N/A excluded and reported separately. | NOT SCORED; this matrix does not claim tests completed. |
| Release blockers | Zero open confirmed Critical/High security findings in shipped scope. Assess severity with impact/exploitability evidence; do not silently downgrade findings or call an accepted risk fixed. | NOT ASSESSED comprehensively. Existing functional High findings remain separate release blockers. |
| Dependency disposition | All detected findings triaged; zero unresolved exploitable Critical/High runtime or build-chain findings for release. Document lower-severity findings, owner and remediation date. | Fresh audit and non-registry component review NOT RUN. |
| Injection/privacy | Zero script/formula executions and zero inventory-bearing remote requests in defined test cases. Include test count, browser and exported artifacts. | Browser/spreadsheet/Network cases NOT RUN. |
| Failure transparency | 100% of agreed invalid/truncated-input cases show correct feedback and allow recovery; no unreported partial success. | NOT SCORED; F3 is a known failure. |

For every tested control record: control/category ID, commit, environment, input, steps/command, actual result, evidence file, status, reviewer, date and linked finding. Release exceptions require an explicit user decision with scope and expiry; they remain exceptions, not a PASS. Routine local edits and reviews do not require approval under this rule.

## Reassessment triggers

Reopen this matrix when adding a server/API, accounts, persistence, remote LLM/extraction, telemetry, remote URL imports, hosting, dependencies or build automation. Review the applicable categories before claiming those features ready. Update tests and evidence together with the implementation.
